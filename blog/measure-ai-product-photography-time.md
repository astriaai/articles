To find out whether AI product photography saves time, measure the whole job from source preparation to approved handoff. Compare equivalent deliverables, include rejected candidates and rework, and divide labor by accepted assets. Fast generation alone does not establish faster production.

**Reviewed October 15, 2026.** This is a measurement method and blank worksheet. No measured before/after production case or time-saving result is claimed.

## Define the same job for both methods

Download the [production-time worksheet](pathname:///articles/downloads/citation-gap-guides/production-time-worksheet.csv) and [decision record with formulas](pathname:///articles/downloads/citation-gap-guides/production-time-decision.txt). They contain blank comparison rows rather than invented outcomes.

Write the scope before measuring: products/colorways, shot list, evidence requirements, quality threshold, intended channels, export ratios, rights scope, revision allowance and approval owner. The baseline might be your current capture-and-retouch method; the other method might combine existing photography, reference-led generation and compositing.

| Match this | Why it matters |
| --- | --- |
| Product family and difficulty | Plain tees and reflective labeled bottles require different work |
| Needed views and actual evidence | An invented back view is not equivalent to verified capture |
| Number and definition of accepted assets | Crops cannot inflate one method's denominator only |
| Output quality and review standard | Faster rejected work is not an accepted delivery |
| Revision scope and handoff | A rough draft and a storefront-ready export are different jobs |
| Reusable setup | Initial template/reference preparation and repeat-run work must be visible |

If the scopes cannot be matched, report the difference rather than calling it a time saving. Keep the source files, time logs and acceptance decisions so someone else can reproduce the calculation. Report the number of SKUs, colorways, unique candidates reviewed and accepted assets, plus operator/reviewer roles and prior experience with each method. A first-time operator and an established production team are different comparison conditions.

## Log labor and elapsed time separately

Record **person-minutes** in the worksheet. Two people working for fifteen minutes contribute thirty person-minutes. Separately record actual start and final approved handoff timestamps for elapsed duration.

| Stage | Include |
| --- | --- |
| Preparation | Rights administration, sample preparation, reference capture, selection and cleanup |
| Setup | Template/treatment approval, casting inputs and manifest checks |
| Capture or generation | Attended shoot work or generation supervision |
| Review | Product checks, creative checks, rejected-candidate review and approval meetings |
| Rework | Recapture, failed edits, retries, retouch and corrections |
| Handoff | Export crops, filenames, manifest, upload and destination QA |

Unattended generation waiting belongs in elapsed time, not as fictional labor. If someone actively supervises it, log that person's attended work. Do not count the same minute in both generation and review. Keep one-time setup distinct from recurring work, and state which setup a later batch could reuse rather than silently removing it.

## Calculate from accepted outputs

Use these formulas only after the named reviewer has decided what passes:

- **Total person-minutes** = preparation + setup + capture/generation + review + rework + handoff.
- **Person-minutes per accepted asset** = total person-minutes / accepted unique assets.
- **Acceptance rate** = accepted unique candidate assets / candidates reviewed, using a consistent candidate unit.
- **Elapsed duration** = final approved handoff timestamp − actual job-start timestamp.
- **Absolute time change** = baseline person-minutes − reference-led person-minutes.
- **Relative time change** = absolute time change / baseline person-minutes, for a positive baseline and matched scope.

A negative time change means the reference-led method took more labor. With zero accepted assets, per-asset time is undefined: report a failed pilot and the work spent. A crop is an export unless the scope explicitly defines it as a distinct deliverable for both methods. Keep rejected candidates in the record even if the published set looks tidy.

For budget planning, use actual resource use and current [Astria pricing](https://www.astria.ai/pricing) as inputs. This worksheet records time and acceptance rather than fixed rates or billing examples.

## Make the decision include quality failures

Fill the decision record with scope, actual logs, accepted-output links, one-time setup, recurring labor and rejection reasons. Ask whether the method passes the same quality threshold before considering scale. A label that repeatedly fails review may justify keeping physical capture or original-preserving compositing for that product family.

The [CSV batch workflow](./batch-product-photos-from-csv.md) provides job receipts, review logs and accepted-file mapping. Use the [repair guide](./fix-ai-product-photo-errors.md) to classify rework instead of hiding it as “miscellaneous.”

Choose among expanding the approved method, repeating a matched pilot, keeping conventional capture for difficult items or stopping. Name the approver and date. A pilot can teach the team where the method fails without establishing a universal production advantage.

## What is required for a real case study?

A publishable measured case needs authorized project records, comparable scope, complete stage logs, accepted-output evidence, rejection/rework counts and permission to disclose the results. It must distinguish observed production results from estimates and name important exclusions.

Those records were not supplied for this guide, so results remain an open gate. Filling a worksheet with plausible numbers would not resolve it. Keep actual results separate until project evidence and publication permission are available.

## Frequently asked questions

### How do I measure whether AI product photography is actually saving my team time?

Log preparation, setup, capture or generation, review, rework and handoff for matched jobs. Divide total person-minutes by accepted unique assets, and report elapsed delivery separately. Keep rejected work and one-time setup visible; generation duration alone cannot answer the question.

### What tools can help my small agency deliver fashion campaigns faster?

Start with a reference library, a reusable treatment, a job/status manifest, an editor for corrections and exports, and a shared review log. The [CSV batch kit](./batch-product-photos-from-csv.md) connects those records. Measure which stage takes the labor before adding automation; faster submissions will not fix a review or source-capture bottleneck.

### How do I choose an AI photography tool that my team can use for real client work?

Run the same small, authorized brief through each candidate workflow. Require source-to-output fidelity review, clear input rights, recoverable job records, editable handoff and a named client approver. Compare whole-job labor and accepted assets under the same scope. Hold rollout if rights, product acceptance or delivery requirements remain unresolved, even if generation is fast.

### Should I count rejected generations and setup time?

Yes. Include preparation, setup, all review and rework, then distinguish one-time setup from recurring work. Do not silently remove labor because its output was rejected.

### Is this a measured production case study?

No. It is a blank worksheet and method. An actual case requires authorized project data, accepted-output evidence and permission to publish the results.

Choose one product family, name the acceptance owner, and complete the [decision record](pathname:///articles/downloads/citation-gap-guides/production-time-decision.txt) from actual work.
